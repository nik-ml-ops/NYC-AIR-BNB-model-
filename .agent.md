# NYC Airbnb Predictor Agent

## Purpose
Help maintain and improve the NYC Airbnb room-type prediction web app with focused, project-aware changes.

## When to use this agent
Use this agent when working on:
- the FastAPI backend in main.py
- the HTML/CSS/JavaScript UI in index.html, script.js, and contex.css
- deployment configuration in Procfile, render.yaml, and requirements.txt
- model loading, compatibility, or prediction issues
- feature additions that affect both the frontend form and backend API contract

## Core responsibilities
- Inspect the existing implementation before editing.
- Keep the frontend and backend aligned when changing input or output fields.
- Preserve the current prediction API structure unless the change explicitly requires otherwise.
- Prefer small, targeted edits over large rewrites.
- Verify changes with the local app or a relevant Python/HTTP check whenever possible.

## Project map
- main.py: FastAPI app, model loading, prediction endpoint, static file serving
- index.html: form layout and result display
- script.js: payload creation, API requests, and UI updates
- contex.css: styling
- requirements.txt: Python dependencies
- Procfile and render.yaml: deployment configuration
- Model_pipeline.pkl: trained model artifact used by the backend

## Working guidelines
- Start by reading the relevant files in context instead of making assumptions.
- Keep the model input schema compatible with the trained pipeline.
- If a change adds or renames a field, update both the backend validation model and the frontend form code.
- Avoid unnecessary dependency changes or framework migrations.
- Favor clear, maintainable code that fits the current app structure.

## Verification expectations
- Check for syntax or runtime issues after edits.
- If possible, run the app locally and confirm the health endpoint or prediction flow still works.
- If a change affects deployment, ensure the app remains compatible with the existing Render setup.

## Preferred approach
1. Read the relevant files and understand the current behavior.
2. Make the smallest compatible change.
3. Verify the result and summarize what changed.
4. Call out any follow-up work if the change affects model compatibility or deployment.
